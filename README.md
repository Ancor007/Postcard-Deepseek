# Диагностика POST-кодов ПК на ESP32 + LLM

Выпускная квалификационная работа: аппаратно-программный модуль, который считывает POST-коды с карты **CH311L**, декодирует их на **ESP32** и интерпретирует через **Yandex Cloud LLM**.

Автор: **Салюков Егор Алексеевич**  
Направление: 09.03.01 Информатика и вычислительная техника

## Зачем это нужно

POST-коды AMI, Award и Phoenix несовместимы: один и тот же HEX-код означает разные этапы инициализации. Обычная POST-карта показывает цифры, а расшифровку приходится искать вручную. Этот проект снимает код с индикатора, отдаёт веб-интерфейс и получает диагностическое заключение модели (этап, вероятная причина, что проверить).

## Архитектура

1. **Аппарат** — POST-карта CH311L читает код с PCI; ESP32 снимает сегменты и разряды динамического индикатора (общий анод, мультиплексирование >50 Гц).
2. **Прошивка** — агрегация выборок GPIO → HEX-символ → веб-форма (модель платы / BIOS).
3. **Облако** — REST API Yandex Cloud возвращает структурированный разбор кода.

Поток данных только снизу вверх: сигнал → код → заключение. На устройстве нет статических таблиц интерпретации BIOS.

## Прошивка

Исходник: [`firmware/post_code_reader/post_code_reader.ino`](firmware/post_code_reader/post_code_reader.ino)

Перед сборкой в `namespace cfg` задайте свои значения (в репозитории стоят заглушки, без реальных ключей):

- Wi-Fi SSID / пароль
- Yandex Cloud: API-ключ, ID каталога, ID промпта

Сборка: Arduino IDE (откройте папку `firmware/post_code_reader/`, плата **ESP32**, библиотека **ArduinoJson**) или PlatformIO. После подключения к Wi-Fi веб-интерфейс доступен на порту **80**.

## Испытания

- Штатный POST: считанный код совпал с индикатором карты, модель зафиксировала завершение инициализации.
- Отказ RAM (извлечение модуля): код остановился на инициализации памяти, модель указала на неисправность ОЗУ.
